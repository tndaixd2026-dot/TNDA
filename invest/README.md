# 期末提報「即時投資」互動系統

需求規格見專案根目錄的 [`SPEC.md`](../SPEC.md)。這是一個獨立的子專案，和根目錄的 TNDA Relay 互不影響。

| 頁面 | 給誰用 |
|---|---|
| `…/invest/` | 學生端（手機優先）：輸入姓名登入，像買賣股票一樣分配 100 萬 |
| `…/invest/screen/` | 現場大螢幕（65 吋橫式）：走勢圖＋排行 → 暗盤倒數 → 結果揭曉 |
| `…/invest/screen/?course=wed` | 固定顯示上半場（`thu` 為下半場），不跟著管理員切換 |
| `…/invest/admin/` | 管理員：切換場次、開盤／暗盤／封盤／取消封盤、看誰還沒投完、匯入名單、重置 |

正式網址（GitHub Pages）：`https://tndaixd2026-dot.github.io/TNDA/invest/`

## 架構

```
手機／大螢幕／管理員（GitHub Pages 上的靜態網頁）
        │  HTTPS：POST /rest/v1/rpc/invest_*（每 0.7～2 秒查詢一次）
        ▼
Supabase（Postgres）── supabase/schema.sql：所有規則、結算、暗盤保密、自動封盤
```

- **規則都在資料庫裡**（`supabase/schema.sql`）。網頁只能呼叫 `public.invest_*` 這幾個函式；資料表放在不公開的 `invest` schema，網頁碰不到。不能投自己、單組上限、餘額、開封盤時間、暗盤隱藏、倒扣與結算全部在資料庫端驗證。
- **同步方式是定時查詢**：大螢幕每 0.7 秒、手機與管理員每 2 秒問一次「有沒有變動」，沒變動時回應只有約 50 bytes。現場網路不穩時，每次查詢都是獨立的請求，斷線恢復後下一次查詢就拿到最新狀態，不需要重新連線。學生下單的結果由資料庫直接回傳，不用等查詢。
- **暗盤倒數由資料庫計時**：倒數結束後，下一個查詢或下單就會觸發封盤；封盤時間記為倒數結束的那一刻，結果不受誰先查詢影響。
- **同一場的下單逐筆鎖定處理**，同時大量下單也不會超過餘額。
- **本機版（備援）**：`server/` 用 PGlite（WebAssembly 版的 Postgres）執行同一份 `schema.sql`，並模擬 Supabase 的 RPC 網址。用於開發、自動化測試，也能在 Supabase 出問題時用筆電＋手機熱點撐場。
- `shared/rules.ts` 是同一套規則的 TypeScript 版：前端拿來即時提示，測試拿來和資料庫結算逐一比對。

```
supabase/schema.sql   資料庫：資料表、規則、結算、RPC（Supabase 與本機版共用）
shared/               規則參考實作、名單 CSV 解析、金額格式、型別
src/                  前端（Preact）：pages/Student、Screen、Admin
server/               本機版：PGlite + 模擬 Supabase RPC + 提供網頁
tests/                規則、名單、資料庫端對端（tests/api.test.ts）、瀏覽器實測（tests/e2e）
deploy.config.json    正式版要連的 Supabase 網址與公開金鑰
```

## 上線步驟（Supabase + GitHub Pages）

1. **建立 Supabase 專案**：到 supabase.com 註冊，用免費方案新增專案，地區選 **Northeast Asia (Tokyo)**。
2. **建立資料庫**：專案的 SQL Editor → 貼上 `supabase/schema.sql` 全部內容 → Run。再執行一行設定管理員密碼（可以是中文）：
   ```sql
   select invest.set_admin_password('你的密碼');
   ```
   之後 `schema.sql` 有更新時，重新貼上執行即可（會保留資料）。
3. **填入連線設定**：專案的 Project Settings → API，把 Project URL 和 publishable（或 anon）key 填進 `deploy.config.json`。這兩個值本來就是公開給網頁用的，可以提交到 git；資料庫密碼與 secret／service_role key **不要**放進來。
4. **部署**：合併到預設分支後，GitHub Actions 會測試、建置並發布到 GitHub Pages。
5. **匯入名單**：打開 `…/invest/admin/`，用管理員密碼登入 → 名單 → 貼上 CSV → 預覽 → 確認匯入。

**保持喚醒**：Supabase 免費專案 7 天沒有使用會自動暫停。`.github/workflows/invest-keepalive.yml` 每 3 天呼叫一次，讓專案保持喚醒（要合併到預設分支才會開始排程）。活動前一天也可以在 Supabase 後台確認專案狀態是 Active。

免費方案的限制和本系統的用量：約 50 人在線時，每秒大約 25～30 個查詢，每個查詢在資料庫裡不到 2 毫秒；沒有使用 Supabase 的即時推播（Realtime），所以不受它每秒 100 則訊息的限制。

## 本機開發與本機版

需要 Node.js 22.18 以上。

```bash
cd invest
npm install
npm run dev               # 本機資料庫 + API :8787 + 前端 :5173（管理員密碼 admin）
npm test                  # 規則、名單、資料庫端對端
npm run test:e2e          # 用 Chromium 操作三個頁面（需要 Chromium）
npm run typecheck
```

本機版（現場備援：筆電＋手機熱點；或任何能跑 Node／Docker 的主機）：

```bash
npm ci
npm run build:local
ADMIN_PASSWORD='你的密碼' npm start
```

| 環境變數 | 預設 | 說明 |
|---|---|---|
| `ADMIN_PASSWORD` | 開發模式為 `admin` | 管理員密碼，可以是中文。`NODE_ENV=production` 時沒設定會拒絕啟動 |
| `PORT` | `8787` | |
| `HOST` | `0.0.0.0` | |
| `DATA_DIR` | `./data` | 資料庫檔案存放處，要放在重啟後不會消失的地方 |
| `DARK_SECONDS` | `300` | 暗盤長度（秒）。彩排時可以設短一點，正式活動請保持預設 |

啟動時終端機會印出區網網址（`http://192.168.x.x:8787`）。手機和筆電連同一個熱點／Wi-Fi 就能直接用；需要公開網址時可搭配 `cloudflared tunnel --url http://localhost:8787`。本目錄的 `Dockerfile` 也是本機版。

本機版沒有名單時會放入假名單（週三 20 人 5 組、週四 28 人 7 組，其中 10 人兩堂都有），方便彩排。

## 現場網路建議

- 系統放在雲端（Supabase + GitHub Pages），學生用自己的 4G／5G 就能連，不依賴現場 Wi-Fi。開場時提醒：Wi-Fi 不穩就關掉 Wi-Fi 改用行動網路。
- 大螢幕那台電腦準備一支手機開熱點當備援。
- 斷線時畫面會顯示「重新連線中…」，恢復後自動補上最新狀態。學生下單若因斷線沒送出，會看到「連線失敗」提示，金額以資料庫為準，不會算錯。

## 活動當天流程

1. **事前**：管理員頁 → 名單 → 匯入正式名單 CSV，展開檢查兩堂課的組別與人數。
2. **彩排**：開盤 → 用幾支手機下單 → 進入暗盤 → 立即封盤，確認大螢幕與手機都正常 → 「重置」該場（會清掉投資、走勢、結果與出席紀錄）。
3. **上半場**：場次選「上半場・週三」→ 學生掃大螢幕 QR code 登入 → 開盤 → 報告進行中 → 封盤前 5 分鐘按「進入暗盤」→ 倒數結束自動封盤，大螢幕揭曉結果（備用：「立即封盤」；誤按可「取消封盤」）。
4. 管理員頁「下載結果 CSV」留存（含姓名明細）。
5. **下半場**：場次切到「下半場・週四」，重複步驟 3、4。上半場結果會保留，學生端也看得到自己上半場的成績。

管理員頁的「還沒投完」清單可以在暗盤前提醒還有餘額的同學（標示「會倒扣」的是有登入的人）。

## 名單

CSV 每行「姓名, 課堂, 組別」，第一行標題可有可無；課堂填 `週三`／`週四`（也接受 `三`、`上半場`、`wed` 等）。可以上傳檔案，或從 Google 試算表直接複製貼上（Tab 分隔）。

```
姓名,課堂,組別
王小明,週三,第1組
王小明,週四,第3組
```

- 同一人修兩堂課就寫兩行，兩堂課的組別可以不同；兩堂課的 100 萬互不相通。
- 匯入只會取代 CSV 裡有出現的課堂，另一堂不受影響。已封盤的場次要先重置才能改名單。
- 開盤中也可以匯入（例如臨時補人）；預覽會列出因為換組或被移除而退回的投資。
- 組別寫成「第2組：看到太陽就知道完蛋了」時，畫面會顯示「第2組」加上組名；組別依組號排序（阿拉伯數字或中文數字皆可）。
- 正式名單含真實姓名，**不要提交到 git**，請由管理員頁匯入。

## 已確認的規則細節

規格沒寫明的地方，以下是和老師確認過的做法：

1. **缺席、沒登入的同學不倒扣**。只有「這一場有登入過」的人，封盤時沒投完的錢才會從自己那組倒扣。登入過 = 這一場是目前場次時開著學生頁（手機每 15 秒回報一次），或有下單。彩排後按「重置」會清掉出席紀錄。
2. **結果排行榜只列各組**：投資總額、倒扣、最終金額、倍率，不列學生姓名。股神獎只顯示得獎者。含姓名的完整明細只在管理員的「下載結果 CSV」。
3. **金額最小單位 1 元**。學生端可以直接輸入以「萬」為單位、小數點後最多 4 位的金額（例如 12.3456 萬 = 123,456 元），畫面也精確顯示到 1 元。
4. **最高的組即使是負數，一樣拿一飛沖天獎**；同分並列。
5. **個人名次的分母只算有投資的人**；沒投資的人不列入個人排名。這一場沒有人投資時，股神獎從缺。
6. **不加個人代碼**，現場只輸入姓名登入（規格 11）。代價是知道別人姓名就能看到對方的投資，已知並接受。
7. **可以取消封盤**（誤按時用）：撤回結果、保留所有投資。暗盤中手動封盤、倒數還沒結束 → 回到暗盤接續剩下的倒數；其他情況 → 回到開盤中。
8. **名單**：Notion「學生名單｜互動兩堂課」，週三＝115-1 VSAI（用「W9 分組」，5 組），週四＝115-1 跨域數位製作實務（用「115-1 跨域分組」，7 組）；期中棄選的同學排除；組名照 Notion 原文顯示。
9. **管理員密碼**用 `invest.set_admin_password(…)`（Supabase）或 `ADMIN_PASSWORD`（本機版）設定，可以是中文。密碼不寫進程式碼與 git。
